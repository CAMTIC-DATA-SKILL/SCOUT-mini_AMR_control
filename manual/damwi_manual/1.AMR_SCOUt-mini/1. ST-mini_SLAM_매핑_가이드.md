# CAMTIC ST-mini SLAM 매핑 가이드

로봇을 켜서 지도를 만들고 저장하기까지의 순서입니다. 기본 사용법은 「CAMTIC ST-mini 사용 매뉴얼」을 함께 참고하세요.

## 0. 시작 전에

**명령어 실행 위치 표시**

| 표시 | 실행하는 곳 | 프롬프트 |
|---|---|---|
| 내 PC | 접속하는 담당자의 PC | (PC마다 다름) |
| camtic_dev 안 | 로봇 안의 개발 공간 (ROS 2 사용) | `root@camtic:/home/camtic#` |
| 로봇 PC | 로봇의 기본 터미널 | `camtic@camtic:~$` |

- `<꺾쇠>` 부분은 실제 값으로 바꿔 입력합니다 (꺾쇠는 입력하지 않음).
- 로봇에 접속하면 자동으로 `camtic_dev` 안으로 들어옵니다. 로봇 PC 명령은 `exit`를 한 번 입력해 나온 뒤 실행합니다.

> ⚠️ **안전**: 조종 중 바퀴가 움직입니다. 주변에 사람과 장애물이 없는 넓은 곳에서 진행하고, 배터리를 충분히 충전한 상태로 시작하세요.

**꼭 지킬 것**

- **운영 모드(`camtic-robot-nav`, `camtic-robot-zenoh`)와 동시에 실행하지 않습니다.**
- 자율주행 런치(`camtic_bringup.launch.py`)와 SLAM 런치를 **동시에 실행하지 않습니다.** 지도 위치 추정이 서로 충돌합니다.
- 기존 작업 폴더 `/home/camtic/camtic_ws`는 수정하지 않습니다. 지도는 새 작업 폴더(`/home/camtic/my_ws`)에 저장합니다.

## 1. 접속

로봇 전원을 켜고 1~2분 기다린 뒤 접속합니다.

```bash
# 내 PC
ssh camtic@<로봇 주소>      # 랜선 직결: 192.168.1.211 / 와이파이: 192.168.1.220
```
NoMachine 접속 가능

---

## 2. 사전 점검 (실행 전 정리)

```bash
# camtic_dev 안
ip -br link show can0        # UP 이면 정상
pgrep -x scout_base_node     # 숫자가 나오면 아래 pkill 실행
pkill -x scout_base_node
ros2 node list               # 아무 노드도 없어야 정상
```

```bash
# 로봇 PC  (exit 로 한 번 나온 뒤)
docker ps                    # camtic_nav, camtic_zenoh 가 없어야 정상
```

- `ros2 node list`에 `amcl`, `map_server`, `bt_navigator` 등이 보이면 자율주행이 아직 켜져 있는 것입니다. 해당 터미널에서 `Ctrl + C`로 끄세요.

---

## 3. SLAM 실행

```bash
# camtic_dev 안 (터미널 1)
ros2 launch camtic_bringup slam_bringup.launch.py    # 바퀴 + 센서 + SLAM
```

이 터미널은 매핑이 끝날 때까지 닫지 않습니다.

---

## 4. 정상 동작 확인

새 터미널을 열어 접속합니다 (자동으로 camtic_dev 안).

```bash
# camtic_dev 안 (터미널 2)
ros2 topic hz /wheel_odom     # 약 50Hz
ros2 topic hz /scan           # 약 10Hz
ros2 topic echo --once /scout_status    # error_code: 0, 배터리 전압 표시
ros2 node list                # slam_toolbox 노드가 보이고, amcl / map_server 는 없어야 정상
```

---

## 5. 조종하며 지도 만들기

```bash
# camtic_dev 안 (터미널 3)
ros2 run teleop_twist_keyboard teleop_twist_keyboard
```

> teleop 패키지가 없으면 `apt update && apt install -y ros-humble-teleop-twist-keyboard` (camtic_dev를 새로 만들면 사라집니다)

키보드, 컨트롤러 모두 조종 가능

**매핑 요령**

- **천천히** 이동합니다. 급가속, 급회전은 지도가 어긋나는 원인이 됩니다.
- 제자리에 있으면 지도가 갱신되지 않습니다. 일정 거리 이상 이동하거나 회전해야 갱신됩니다.
- 벽과 고정 구조물이 많이 보이는 경로로 다니고, 같은 구역을 한 바퀴 돌아 출발점으로 돌아오면 지도가 더 잘 맞춰집니다.
- 사람이 라이다 앞을 지나다니면 지도에 흔적이 남을 수 있으니 가급적 피합니다.

## 6. RViz2로 확인 (선택)

로봇 PC에 모니터를 연결하고 로봇 PC 터미널에서 실행합니다.

```bash
# camtic_dev 안
rviz2
```

RViz2 설정:

| 항목 | 값 |
|---|---|
| Fixed Frame | `map` |
| Add → Map | Topic: `/map`, Durability Policy: `Transient Local` |
| Add → LaserScan | Topic: `/scan` |
| Add → TF | - |

- 화면이 이상해도 `ros2 topic hz /map`에 숫자가 나오면 SLAM은 정상입니다.

---

## 7. 지도 저장

**SLAM(터미널 1)을 끄기 전에** 저장합니다.

```bash
# camtic_dev 안
mkdir -p /home/camtic/my_ws/maps
ros2 run nav2_map_server map_saver_cli -f /home/camtic/my_ws/maps/<지도 이름>
```

`<지도 이름>.pgm`(지도 이미지)과 `<지도 이름>.yaml`(해상도·원점 정보) 두 파일이 생깁니다.

저장 확인:

```bash
# 로봇 PC
ls -l /home/camtic/my_ws/maps
```

> ⚠️ `camtic_ws/src/camtic_bringup/maps/map.yaml`은 자율주행 기본 지도입니다. **덮어쓰지 마세요.**

내 PC로 가져오기:

```bash
# 내 PC
scp camtic@<로봇 주소>:/home/camtic/my_ws/maps/<지도 이름>.* C:\User\USER\Desktop\
```

## 8. 종료

1. 터미널 3(조종)과 터미널 1(SLAM)에서 `Ctrl + C`
2. 로봇을 끌 때는 로봇 PC에서 `sudo poweroff` (전원 버튼 길게 누르기 금지)

## 9. 문제 해결

| 증상 | 확인 | 해결 |
|---|---|---|
| 지도가 갱신되지 않음 | `ros2 topic hz /map`, `ros2 topic hz /scan` | 로봇을 실제로 이동·회전시킵니다. `/scan`이 안 나오면 라이다 연결(USB)을 확인 |
| `map → base_link` 값이 `[0, 0, 0]`에서 고정 | `ros2 node list`에 `amcl` 등 자율주행 노드가 있는지 | 자율주행을 끄고 SLAM만 다시 실행 (2번부터) |
| `/wheel_odom`이 안 나옴 | `pgrep -x scout_base_node` | 2번 정리 후 SLAM 재실행. `can0`이 DOWN이면 베이스 전원과 USB-CAN 연결 확인 |
| `can0`가 DOWN | `journalctl -t can0-watchdog -n 20` (로봇 PC) | 자동 복구가 켜져 있는지 확인, 베이스 전원 확인 |
| RViz2에서 지도가 안 보임 | `/map` 토픽 수신 여부 | Durability를 `Transient Local`로 설정, 소프트웨어 렌더링으로 실행 |
| `ros2` 명령이 없다고 나옴 | 프롬프트가 `camtic@`인지 | `docker exec -it camtic_dev bash`로 camtic_dev 안으로 들어감 |
| 지도가 어긋나거나 겹쳐 보임 | 이동 속도 | 천천히 다시 매핑. 문제가 계속되면 SLAM을 끄고 처음부터 다시 실행 |

그래도 해결되지 않으면 넥스루트 주식회사에 문의하세요.
