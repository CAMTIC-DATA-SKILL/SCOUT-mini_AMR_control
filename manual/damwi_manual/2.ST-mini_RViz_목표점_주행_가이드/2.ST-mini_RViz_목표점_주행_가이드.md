# CAMTIC ST-mini 저장 지도 주행 가이드 (RViz 목표점 이동)

「SLAM 매핑 가이드」로 만든 지도를 불러와서, RViz2에서 목표점을 찍어 로봇을 이동시키는 순서입니다. 기본 사용법은 「CAMTIC ST-mini 사용 매뉴얼」을 함께 참고하세요.

## 0. 시작 전에

**명령어 실행 위치 표시**

| 표시 | 실행하는 곳 | 프롬프트 |
|---|---|---|
| 내 PC | 접속하는 담당자의 PC | (PC마다 다름) |
| camtic_dev 안 | 로봇 안의 개발 공간 (ROS 2 사용) | `root@camtic:/home/camtic#` |
| 로봇 PC | 로봇의 기본 터미널 | `camtic@camtic:~$` |

- `<꺾쇠>` 부분은 실제 값으로 바꿔 입력합니다 (꺾쇠는 입력하지 않음).
- 로봇에 접속하면 자동으로 `camtic_dev` 안으로 들어옵니다. 로봇 PC 명령은 `exit`를 한 번 입력해 나온 뒤 실행합니다.

> ⚠️ **안전**: 목표점을 찍으면 로봇이 **스스로 움직입니다.** 주행 경로 주변에 사람과 장애물이 없는 곳에서 진행하고, 주행 중에는 항상 로봇 곁에서 지켜보세요. 최고 속도는 0.4 m/s, 회전은 1.7 rad/s로 설정되어 있습니다. 배터리는 충분히 충전한 상태로 시작합니다.

**꼭 지킬 것**

- **운영 모드(`camtic-robot-nav`, `camtic-robot-zenoh`)와 동시에 실행하지 않습니다.**
- **SLAM 런치와 동시에 실행하지 않습니다.**
- 이 문서의 2번(지도 교체) 외에는 기존 작업 폴더 `/home/camtic/camtic_ws`를 수정하지 않습니다.

## 1. 접속

로봇 전원을 켜고 1~2분 기다린 뒤 접속합니다.

```bash
# 내 PC
ssh camtic@<로봇 주소>      # 랜선 직결: 192.168.1.211 / 와이파이: 192.168.1.220
```
NoMachine 접속 가능

## 2. 지도 적용

자율주행은 `/home/camtic/camtic_ws/src/camtic_bringup/maps/map.yaml`을 지도로 읽습니다. 이름이 `map`인 파일을 새 지도로 바꿔서 사용합니다.

> ⚠️ 이 폴더의 `map` 파일은 **운영 모드도 함께 사용합니다.** 바꾸기 전에 반드시 백업하세요. 지도 폴더 외의 `camtic_ws` 파일은 수정하지 않습니다.

```bash
# camtic_dev 안
# 1) 기존 지도 전체 백업
mkdir -p /home/camtic/my_ws/maps_backup
cp -a /home/camtic/camtic_ws/src/camtic_bringup/maps/. /home/camtic/my_ws/maps_backup/

# 2) 새 지도를 map.pgm / map.yaml 이름으로 복사
cp /home/camtic/my_ws/maps/<지도 이름>.pgm  /home/camtic/camtic_ws/src/camtic_bringup/maps/map.pgm
cp /home/camtic/my_ws/maps/<지도 이름>.yaml /home/camtic/camtic_ws/src/camtic_bringup/maps/map.yaml

# 3) yaml 안의 image 줄을 새 파일명으로 변경 (중요)
sed -i 's#^image:.*#image: map.pgm#' /home/camtic/camtic_ws/src/camtic_bringup/maps/map.yaml
cat /home/camtic/camtic_ws/src/camtic_bringup/maps/map.yaml
```

`image: map.pgm` 줄이 보이면 정상입니다. 이 줄을 바꾸지 않으면 지도를 읽지 못합니다. 지도를 바꾼 뒤 다시 빌드할 필요는 없습니다.

## 3. 사전 점검 (실행 전 정리)

```bash
# camtic_dev 안
ip -br link show can0        # UP 이면 정상
pgrep -x scout_base_node     # 숫자가 나오면 아래 pkill 실행
pkill -x scout_base_node
ros2 node list               # 아무 노드도 없어야 정상
```

```bash
# 로봇 PC  (exit 로 한 번 나온 뒤)
docker ps                    # camtic_nav, camtic_zenoh 가 없어야 정상
```

`ros2 node list`에 `slam_toolbox`나 `amcl`이 남아 있으면 이전 실행이 켜져 있는 것입니다. 해당 터미널에서 `Ctrl + C`로 끄세요.

## 4. 자율주행 실행

> ⚠️ 시작할 때 `simple_relocalization`이 **제자리 회전**을 합니다. 로봇 주변을 비우고, 처음에는 바퀴를 바닥에서 띄운 상태로 확인하는 것을 권장합니다.

로봇을 **지도를 만들기 시작한 위치**에 놓고 실행하면 위치를 쉽게 잡습니다.

```bash
# camtic_dev 안 (터미널 1)
ros2 launch camtic_bringup camtic_bringup.launch.py    # 바퀴 + 센서 + 자율주행 + 위치 복원
```

이 터미널은 주행이 끝날 때까지 닫지 않습니다.

## 5. 정상 동작 확인

새 터미널을 열어 접속합니다 (자동으로 camtic_dev 안).

```bash
# camtic_dev 안 (터미널 2)
ros2 lifecycle get /map_server          # active 이면 정상
ros2 lifecycle get /amcl                # active 이면 정상
ros2 lifecycle get /bt_navigator        # active 이면 정상
ros2 topic hz /wheel_odom               # 약 50Hz
ros2 topic hz /scan                     # 숫자가 계속 나옴
ros2 topic echo --once /amcl_pose       # 위치 추정값 (x, y가 시작 위치 근처이면 정상)
```

`ros2 run tf2_ros tf2_echo map base_link` 실행 직후 `frame does not exist` 경고가 한 번 나오는 것은 TF가 아직 도착하기 전이라 나오는 경고입니다. 이어서 값이 나오면 정상입니다.

## 6. RViz2 실행 · 설정

로봇 PC에 모니터를 연결하고 로봇 PC 터미널에서 실행합니다.

```bash
# camtic_dev 안
rviz2
```

RViz2 설정:

| 항목 | 값 |
|---|---|
| Fixed Frame | `map` |
| Add → Map | Topic: `/map`, Durability Policy: `Transient Local` |
| Add → LaserScan | Topic: `/scan`, Reliability: `Best Effort`, Size 0.05, 눈에 띄는 색(예: 빨강) |
| Add → TF | - |

- 화면이 깨지면 `LIBGL_ALWAYS_SOFTWARE=1 rviz2`로 실행합니다.
- 설정을 저장해 두면 다음에 다시 만들지 않아도 됩니다.

```bash
# camtic_dev 안  (RViz 메뉴 File → Save Config As 로 저장하기 전에 폴더를 먼저 만듭니다)
mkdir -p /home/camtic/my_ws/rviz
# 저장 경로: /home/camtic/my_ws/rviz/nav.rviz
# 다음부터 실행
rviz2 -d /home/camtic/my_ws/rviz/nav.rviz
```

## 7. 초기 위치 맞추기

라이다 점(빨강)이 지도의 검은 벽선 위에 **거의 포개져야** 정상입니다. 어긋나 있으면 위치를 알려 줍니다.

1. 상단 툴바의 **2D Pose Estimate**를 클릭합니다.
2. 지도에서 **로봇의 실제 위치**를 클릭한 채로, 로봇이 바라보는 방향으로 드래그합니다.
3. 라이다 점이 벽에 맞을 때까지 반복합니다.

시작 직후 위치가 엉뚱하면 `simple_relocalization`이 복원한 이전 위치가 틀렸을 수 있습니다. 위 방법으로 다시 맞추세요.

---

## 8. 목표점 찍어서 이동

1. 상단 툴바의 **2D Goal Pose**를 클릭합니다.
2. 지도의 **빈 공간**을 클릭한 채로, 도착했을 때 로봇이 바라볼 방향으로 드래그합니다.
3. 로봇이 경로를 계산해 이동합니다. 터미널 1의 로그와 로봇 움직임을 함께 봅니다.

**처음에는 현재 위치에서 1m 정도 앞** 목표로 시험하고, 잘 되면 거리를 늘립니다.

도착 확인:

```bash
# camtic_dev 안 (터미널 2)
ros2 topic echo --once /amcl_pose
```

**이동 중 멈추기**

```bash
# camtic_dev 안 (터미널 2)  — 진행 중인 목표 모두 취소
ros2 service call /navigate_to_pose/_action/cancel_goal action_msgs/srv/CancelGoal "{}"
```

```bash
# camtic_dev 안 (터미널 2)  — 정지 명령을 계속 보내 최우선으로 멈춤 (Ctrl + C로 해제)
ros2 topic pub -r 10 /cmd_vel_pause geometry_msgs/msg/Twist "{}"
```

> 위 정지 방법은 처음 사용하기 전에 **바퀴를 띄운 상태에서 동작을 먼저 확인**하세요.

---

## 9. 종료

1. 터미널 1(자율주행)에서 `Ctrl + C`
2. RViz2 창을 닫습니다.
3. 로봇을 끌 때는 로봇 PC에서 `sudo poweroff` (전원 버튼 길게 누르기 금지)

## 10. 문제 해결

| 증상 | 확인 | 해결 |
|---|---|---|
| 라이다 점이 지도와 안 맞음 | RViz 화면 | 7번의 2D Pose Estimate로 위치 다시 지정 |
| 지도가 RViz에 안 보임 | `ros2 lifecycle get /map_server` | `active`가 아니면 `map.yaml`의 `image:` 줄과 `map.pgm` 파일 존재 확인 (2번) |
| `/amcl_pose`가 안 나옴 | `ros2 lifecycle get /amcl` | `active`가 아니면 터미널 1 로그 확인, 3번 정리 후 재실행 |
| 목표를 찍어도 안 움직임 | `ros2 lifecycle get /bt_navigator`, `ros2 topic hz /wheel_odom` | `active` 확인. `/wheel_odom`이 안 나오면 `pgrep -x scout_base_node`, `can0` 상태 확인 |
| 목표 근처에서 계속 미세하게 움직임 | 목표 위치 | 도착 허용 오차가 작게(위치 0.08m, 방향 약 3°) 설정되어 있습니다. 목표를 다시 지정하거나 방향을 크게 신경 쓰지 않는 위치로 지정 |
| `map → base_link` 값이 `[0, 0, 0]`에서 고정 | `ros2 node list`에 SLAM 노드가 있는지 | SLAM을 끄고 3번부터 다시 시작 |
| `ros2` 명령이 없다고 나옴 | 프롬프트가 `camtic@`인지 | `docker exec -it camtic_dev bash`로 camtic_dev 안으로 들어감 |

그래도 해결되지 않으면 넥스루트 주식회사에 문의하세요.
